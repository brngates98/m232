# Motronic 2.3.2 ECU Firmware Decompilation

This directory contains decompiled assembly code for the Motronic 2.3.2 ECU firmware binary files.

## Overview

The Motronic 2.3.2 ECU uses a **Siemens SAB80C515** microcontroller, which is based on the Intel 8051 architecture. The firmware has been decompiled from binary ROM dumps into human-readable 8051 assembly language.

## Files

### Decompiled Assembly Files (.asm)
- `stock_AANABY_27c512.asm` - Stock tune for AAN/ABY engine (64KB ROM, 27c512 EPROM)
- `stock_AANABY_87c257.asm` - Stock tune for AAN/ABY engine (32KB ROM, 87c257 EPROM)  
- `bigturbo_WMI_27c512.asm` - Big turbo tune with WMI (64KB ROM, 27c512 EPROM)
- `bigturbo_WMI_87c257.asm` - Big turbo tune with WMI (32KB ROM, 87c257 EPROM)

### Log Files (.log)
Each `.log` file contains warnings from the disassembly process, primarily about SFR (Special Function Register) addresses that may not have symbolic names defined.

## Technical Details

### Processor Architecture
- **CPU**: Siemens SAB80C515 (Intel 8051 compatible)
- **Features**: 8-bit CMOS single-chip microcontroller with enhanced timers, ADC, and additional I/O ports
- **Memory**: Code stored in external EPROM (27c512 = 64KB, 87c257 = 32KB)

### Disassembly Tool
The firmware was decompiled using [disasm51](https://github.com/OlekMazur/disasm51), a Python-based disassembler specifically designed for 8051/8052 microcontrollers.

### MCU Definition
The file `sab80c515.mcu` in the root directory contains Special Function Register (SFR) definitions for the SAB80C515 processor, including:
- Standard 8051 SFRs (ports, timers, serial, interrupts)
- Extended SAB80C515 features (Timer 2, ADC, DAC, additional ports)
- Interrupt vector addresses

## Understanding the Assembly Code

### Structure
Each `.asm` file includes:
1. **Header comments** - Generated by disasm51, includes source file info
2. **Include directive** - References the SAB80C515 MCU definition file
3. **Code segment (cseg)** - Contains the actual program code
4. **Interrupt vectors** - Labeled entry points (RESET, EXTI0, TIMER0, etc.)
5. **Jump tables and data** - Data blocks embedded in code space
6. **Program code** - Disassembled 8051 assembly instructions

### Labels and References
- `RESET:` - Reset vector at address 0000h (program entry point)
- `EXTI0:`, `EXTI1:` - External interrupt handlers
- `TIMER0:`, `TIMER1:`, `TIMER2:` - Timer interrupt handlers
- `SINT:` - Serial interrupt handler
- `jump_XXXX:` - Code labels for jump targets
- `dptr_XXXX:` - Data pointer references

### Common 8051 Instructions
- `MOV` - Move data between registers/memory
- `LJMP`, `SJMP`, `JMP` - Jump instructions
- `LCALL`, `ACALL`, `RET` - Call and return from subroutines
- `CLR`, `SETB` - Clear/set bits
- `ADD`, `SUBB`, `MUL`, `DIV` - Arithmetic operations
- `ANL`, `ORL`, `XRL` - Logical operations
- `MOVC` - Move from code memory (read from ROM)

## Comparison

By comparing the stock and big turbo tunes, you can identify modifications made for the big turbo setup:
- Fuel injection timing adjustments
- Boost pressure control changes
- WMI (Water Methanol Injection) integration
- Safety/failsafe mechanisms

## Reassembly

The generated assembly code can be reassembled back to a binary file using an 8051 assembler such as:
- [asem-51](http://plit.de/asem-51) - Recommended, compatible with disasm51 output
- [SDCC](http://sdcc.sourceforge.net/) - Open source 8051 toolchain

## Warnings

The `.log` files contain warnings about "unknown SFR" addresses. These are benign and indicate:
- SFRs that are used in the code but don't have symbolic names in our MCU definition
- The disassembly is still correct; hex addresses (e.g., `0E0h`) are used instead of names
- These can be resolved by adding more SFR definitions to `sab80c515.mcu`

## Decompilation Process

To regenerate the decompiled files, run:
```bash
python3 decompile.py
```

This script:
1. Reads each `.bin` file from the `ECU/` directory
2. Invokes disasm51 with the SAB80C515 MCU definition
3. Outputs assembly files to the `decompiled/` directory
4. Captures warnings to `.log` files
